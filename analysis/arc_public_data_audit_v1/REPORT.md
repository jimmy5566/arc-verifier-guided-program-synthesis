# ARC Public Data Audit V1

## Executive conclusion

SFT139 does not need another blind pass over its old corpus. Its original offline training was already large and coherent: 104,539 underlying puzzles expanded to 3,255,481 samples, with about 89.7% of samples coming from NVARC synthetic families. The correct next move is therefore **distribution expansion**, not simple scale replay.

The best Phase-1 public-data source is **ARC-Heavy / BARC synthetic**, followed by **permissively licensed, genuinely novel subsets of arc-dataset-collection**. NVIDIA Nemotron is extremely useful, but mostly as a **lineage + difficulty + success index** because its problem pool is constructed from ARC-AGI-2, NVARC Augmented Puzzles and arc-dataset-collection rather than being a wholly new grid source.

SOAR (5M) and Trelis (102k programs) should be used primarily to infer rule families and program abstractions, not directly fed into SFT139's 16-token grid-only interface.

## What SFT139 already learned

NVARC's final ARChitects dataset contains:

| Source | Unique puzzles | Augmented samples | Share |
|---|---:|---:|---:|
| MINI-ARC | 147 | 37,632 | 1.2% |
| ConceptARC | 160 | 40,960 | 1.3% |
| RE-ARC | 400 | 102,392 | 3.2% |
| ARC-AGI-2 training | 609 | 155,904 | 4.8% |
| NVARC training | 47,337 | 1,132,633 | 34.8% |
| NVARC full | 55,886 | 1,785,960 | 54.9% |
| **Total** | **104,539** | **3,255,481** | **100%** |

The official launcher runs one epoch, global batch 256, 12,716 max steps, BF16, LR 1e-4, and 32 H100 GPUs (4 nodes × 8). This is a serious full-model SFT, not a lightweight adapter pass.

The official training config places `arc2_evaluation6` in **validation**, not the train list. However the dataset builder serializes both demonstration and test pairs when it builds that validation set, so the public evaluation answers influence validation loss/checkpoint selection and must not be treated as an untouched model-selection holdout.

## Source decisions

### P0 — materialize and process for the new SFT pool

**ARC-Heavy / BARC synthetic**
- About 400k puzzles across four 100k collections.
- MIT according to the collection record.
- Generated by executable input/solution programs.
- Directly compatible with grid-only continued-SFT after filtering.
- Caveat: NVARC's synthetic generation itself used BARC descriptions, so conceptual overlap is plausible. Grid-level and family-level canonical dedup are mandatory.

**arc-dataset-collection: permissive novel subsets**
- The collection currently exposes 20 community datasets.
- NVIDIA's license audit says 16/20 are permissive (12 MIT, 4 Apache-2.0), 1 is DbCL, 3 have unspecified licenses.
- Old SFT139 sources (ARC, ConceptARC, MiniARC, RE-ARC) are excluded.
- Only permissive subsets with standard valid ARC grids enter Phase 1.

### P0 metadata — use, but do not treat as a wholly new corpus

**Nemotron-RL-ARC-AGI-v1**
- 10k released train problems sampled from roughly 66k eligible problems; full eligible pool roughly 73k.
- Carries difficulty, lineage and augmentation metadata.
- Public ARC-AGI-1/2 evaluation IDs are blacklisted from train.
- Seed sources are ARC-AGI-2, NVARC Augmented Puzzles and arc-dataset-collection.
- Therefore whole-dataset training would mostly replay known or adjacent lineages. We will import only novel permissive community rows after lineage filtering.

**Nemotron-SFT-ARC-AGI-v1**
- 304,491 successful runs over 72,980 unique problems; curated wide blend 67,529 problems and deep blend 207,569 records over 64,467 problems.
- Correctness is deterministic exact match.
- Same seed-source problem as Nemotron-RL.
- Very useful as difficulty/success/reasoning metadata, but its natural-language/tool traces are not directly compatible with SFT139's 16-token grid-only vocabulary.

### P1 — tagging/curriculum resources

**SOAR**
- Roughly 5M ARC program-synthesis solutions, MIT.
- Mixes solutions to original ARC tasks with hindsight-relabelled synthetic tasks.
- High value for program AST taxonomy and rule-family discovery.
- Not a direct Phase-1 grid corpus until lineage and synthetic-task reconstruction are verified.

**Trelis arc-agi-2-all-100**
- 102,322 Python programs over 1,027 ARC tasks, Apache-2.0.
- Includes correct, partially correct and valid-grid-but-wrong programs.
- Excellent for tagging ARC operations and failure families.
- Poor choice as direct grid training because task IDs substantially overlap official ARC training.

### P1 hold

**Fraser/arc-agi-synthetic**
- 4,940 executable, self-consistent tasks.
- Strong novelty signal and useful rule metadata.
- The card explicitly acknowledges possible cross-task near duplicates.
- No explicit dataset license was located in this audit, so it is tag/dedup-only until licensing is clarified.

### P2 experimental

**GIFARC**
- Current HF release describes 10,000 Python-defined tasks; project repo is MIT.
- Potentially highly novel analogy-derived transformations.
- Third-party GIF provenance needs separate review, so it is not part of the first training pool.

**P-ARC**
- 50 generator/verifier tasks.
- Useful diagnostic set but too small for core training and HF license is "other".

## Important contamination rule

For scientific evaluation, remove all official ARC-AGI-1/2 public evaluation IDs from training and model selection.

Additionally, **exclude NVARC lineage from the "new data" claim**. NVARC full synthetic was built using both ARC-AGI-2 training and evaluation puzzle sources, so exact official-ID blacklisting alone is not enough to make NVARC descendants a clean novel-family source.

## CPU stage

The next stage is not model training. It is a high-concurrency deterministic data build:

1. Materialize P0 sources.
2. Normalize to one ARC task schema.
3. Apply evaluation blacklist.
4. Remove old SFT139/NVARC lineage.
5. Exact canonical task dedup.
6. D4 + color-permutation + train-order equivalence dedup.
7. Program-AST tagging where code exists.
8. Grid-heuristic tagging where code is absent.
9. Freeze whole-family train/val/test split.
10. Emit hashes and curriculum manifests.

Only after these artifacts are frozen should the 3090 be used.

## GPU stage after CPU freeze

1. **M0 diagnostic:** SFT139 teacher-forced Gold Top1/Top5/NLL + greedy exact, broken down by the new family labels.
2. Build failure-weighted curriculum from M0 weaknesses.
3. **M1a:** 3090 QLoRA continued-SFT on roughly 5k–10k novel tasks (after filtering), with 20–30% old replay.
4. Re-evaluate on frozen family-held-out validation.
5. Only if M1a is positive, scale task count / augmentations or rent stronger GPU for production full continued-SFT.
